# Разработка

Выполняйте команды из корня репозитория. Используйте версии Node.js и pnpm из `package.json` и существующий lockfile.

## Подготовка репозитория

```sh
pnpm install --frozen-lockfile
pnpm test
```

Структура кода описана в [архитектуре](./architecture.md). Публичные экспорты определены в `src/index.ts`; примеры и регрессионные тесты обычно используют эту точку входа.

## Команды

| Команда | Назначение |
| --- | --- |
| `pnpm test` | Запустить тесты |
| `pnpm test:watch` | Запускать тесты во время редактирования |
| `pnpm lint` / `pnpm lint:fix` | Проверить оформление кода / применить автоматические исправления |
| `pnpm typecheck` | Проверить библиотеку, тесты, примеры и скрипты через TypeScript |
| `pnpm check:package` | Собрать, упаковать и проверить установленный архив в независимых потребителях ESM и CommonJS |
| `pnpm check:library` | Запустить lint, TypeScript, тесты и проверку пакета |
| `pnpm check:release` | Выполнить проверки библиотеки, проверить и собрать документацию |
| `pnpm docs:dev` | Запустить сайт документации локально |
| `pnpm docs:check` | Проверить ссылки и структуру русских и английских страниц |
| `pnpm docs:build` | Собрать сайт документации |
| `pnpm docs:preview` | Посмотреть собранный сайт |
| `pnpm example:report` | Получить отчёт из примера пакета в `temp/package/` |
| `pnpm example:tutorials` | Создать и проверить книги руководства в `temp/tutorials/` |

Команды документации `dev`, `check` и `build` сначала выполняют `docs:prepare`. Он подготавливает файлы для скачивания в `docs/public/examples/`; редактируйте исходники в `examples/`, а не сгенерированные копии.

## Примеры и фикстуры

| Расположение | Назначение |
| --- | --- |
| `examples/tutorials/` | Запускаемые скрипты и генератор книг руководства |
| `examples/package/` | Рендер отчёта и чтение формы через установленный пакет |
| `examples/regions/`, `examples/comparison/` | Вложенные области и повтор колонок |
| `examples/choices/`, `examples/validation/` | Выбор объектов и собственные правила полей |
| `test/` | Регрессионные сценарии и точечные тесты алгоритмов |
| `scripts/verify-package.ts` | Установка архива, runtime-экспорты, публичные типы и примеры потребителей |

`example:tutorials` создаёт отчёты с нулём, одной и несколькими записями, форму на 20 пустых строк, заполненные и ошибочные формы, многострочные записи контактов. Локальные результаты генерации сохраняются в игнорируемый `temp/`.

XLSX-фикстуры служат входами регрессионных тестов. Перегенерируйте нужную фикстуру только при намеренном изменении её исходного определения. Редактирование документации не требует пересборки всех фикстур.

## Правила кода

TypeScript работает в строгом режиме, с проверкой неиспользуемых локальных переменных и параметров. В исходниках библиотеки запрещён явный `any`: принимайте внешнее значение как `unknown` и проверяйте его. Публичные результаты и контракты между модулями описывайте явно.

Оформление задаёт ESLint. Основной стиль: два пробела, одинарные кавычки, отсутствие точек с запятой и многострочные блоки. Механические исправления выполняйте через `pnpm lint:fix`; функции разделяйте по ответственности и потоку данных.

Русские и английские страницы должны иметь одинаковые пути и структуру разделов. Код, JSON и книги примеров общие, с нейтральными английскими данными и одним источником.

## Проверка изменения

Начните с затронутых тестов и законченного примера через публичный API. Внутренние импорты нужны в точечных тестах алгоритма. Перед релизом выполните `pnpm check:release`.

| Что изменилось | Что проверить |
| --- | --- |
| Подстановка данных или валидация | Значения и ошибки, отсутствующие данные, пустые повторы и повторное использование шаблона |
| Размещение или координаты метаданных | Ноль, одна и несколько записей; затронутые оси, вложенные или соседние области; ссылки в сохранённом XLSX |
| Выдача или чтение формы | Выдать файл, изменить и сохранить отдельно, прочитать с исходным шаблоном; проверить данные и адреса ячеек в ошибках |
| Публичный API или типы | Установить настоящий архив; проверить выполнение ESM/CommonJS и допустимые/ошибочные вызовы TypeScript |
| Документация | Пройти затронутую инструкцию, проверить скачивание, выполнить `docs:check` и `docs:build` |

Открытие файла библиотекой, которая его записала, не доказывает поведение нативных возможностей Excel. Если изменение касается формул, валидации, рисунков, печати или редактируемых блоков, также откройте и сохраните нужные файлы в целевом табличном приложении. Укажите, что именно проверено; автоматическая проверка пакета этот внешний шаг не выполняет.
